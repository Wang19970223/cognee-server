🎯 1. 产品概述

1.1 项目背景

Everything for Copilot 框架目前已定义了 14 个核心用户场景，涵盖了需求分析、设计测试、开发调试、代码管理、知识沉淀等多个环节。POC 验证表明，Cognee 作为知识图谱引擎，能够显著提升知识检索的准确性和深度推理能力。

然而，目前 Cognee 的能力还停留在本地脚本调用层面，无法被 GitHub Copilot 无缝集成，也无法作为统一的知识服务被多个 Skill 和 Agent 共享调用。

1.2 产品目标

构建一个独立的 Cognee Knowledge Service，为 Everything for Copilot 框架提供统一的知识图谱服务接口，实现：

  • 知识检索：支持自然语言查询，返回结构化的知识结果
  • 知识更新：支持增量更新和全量重建
  • 知识维护：提供知识健康度监控和管理能力
  • 无缝集成：GitHub Copilot Skill 可通过 REST API 调用该服务

1.3 核心价值

价值维度 说明
统一知识入口 所有 Skill/Agent 通过同一个服务访问知识，避免重复建设
知识共享 Prompt Recipes、技术决策、业务术语等知识可在服务层融合
降低 Skill 复杂度 Skill 只需关注业务逻辑，知识检索由服务层封装
可观测性 可监控知识使用情况、健康度，为 OKR 审视提供数据

5.1 Skill 调用流程

以 kb-retriever skill 为例：

5.2 Skill 代码示例 

# .github/skills/kb-retriever/skill.py

import os
import httpx
from typing import List, Dict, Any

class CogneeServiceClient:
    """Cognee 知识服务客户端"""
    
    def __init__(self, base_url: str = None, api_key: str = None):
        self.base_url = base_url or os.getenv("COGNEE_SERVICE_URL", "http://localhost:8000/api/v1")
        self.api_key = api_key or os.getenv("COGNEE_API_KEY")
        self.client = httpx.AsyncClient(timeout=30.0)
    
    async def search(self, query: str, context_type: List[str] = None, max_results: int = 5) -> Dict[str, Any]:
        """自然语言搜索"""
        headers = {"X-API-Key": self.api_key}
        payload = {
            "query": query,
            "context_type": context_type or ["knowledge", "recipes", "decisions"],
            "max_results": max_results,
            "search_type": "insights"
        }
        
        response = await self.client.post(
            f"{self.base_url}/search",
            json=payload,
            headers=headers
        )
        response.raise_for_status()
        return response.json()
    
    async def close(self):
        await self.client.aclose()


async def kb_retriever_skill(query: str) -> str:
    """
    kb-retriever skill 主函数
    
    Args:
        query: 用户的问题，如 "IDAAS 灵活菜单"
    
    Returns:
        格式化的答案
    """
    client = CogneeServiceClient()
    
    try:
        # 1. 调用 Cognee 服务
        result = await client.search(query)
        
        # 2. 格式化结果
        if not result["results"]:
            return "未找到相关信息"
        
        formatted = f"## 关于「{query}」的知识检索结果\n\n"
        
        for item in result["results"]:
            formatted += f"### {item['title']}\n"
            formatted += f"{item['content'][:300]}...\n"
            formatted += f"*来源: [{item['type']}] {item['source']['path']}*\n"
            
            if item.get('related'):
                formatted += f"*相关: {', '.join([r['title'] for r in item['related']])}*\n"
            
            formatted += "\n"
        
        formatted += f"\n> 检索耗时: {result['processing_time_ms']}ms"
        
        return formatted
        
    finally:
        await client.close()

📊 6. 数据模型

6.1 核心实体类型

实体类型 描述 属性示例
Recipe Prompt 配方 title, language, tags, author, created_at
Decision 架构决策记录 title, date, status, impact
Concept 业务概念 name, definition, domain
Code 代码片段 language, file_path, function_name
Bug Bug 记录 severity, status, fix_version
Person 团队成员 name, role, expertise
Project 项目模块 name, tech_stack, owner

6.2 核心关系类型

关系类型 源实体 目标实体 描述
RELATES_TO 任意 任意 一般关联
IMPLEMENTS Code Decision 代码实现了某个决策
FIXES Code Bug 代码修复了某个 Bug
MENTIONS Recipe Concept Recipe 提到了某个概念
AUTHORED_BY Recipe/Decision Person 知识由谁创建
DEPENDS_ON Project Concept/Code 项目依赖

🔒 7. 安全与权限

7.1 认证机制

  • API Key 认证：每个 Skill/Agent 使用独立的 API Key
  • Key 管理：通过内部管理平台生成/吊销 Key
  • 请求签名：可选，对敏感操作增加签名验证

7.2 权限控制

权限级别 允许的操作 适用场景
read 检索知识 所有 Skill/Agent
write 添加/更新知识 知识沉淀命令 (/remember, /index)
admin 删除知识、查看健康度 CCG 成员、Tech Leader

7.3 数据安全

  • 所有知识数据存储在内部网络，不对外暴露
  • 敏感代码片段脱敏处理
  • 审计日志记录所有写操作

8.1 性能指标

指标 目标值 说明
检索 P95 延迟 < 500ms 95% 的检索请求在 500ms 内返回
索引吞吐量 > 100 文档/分钟 增量索引能力
并发请求 > 50 QPS 支持团队同时使用
可用性 99.9% 核心服务 SLA

8.2 可扩展性

  • 知识图谱支持水平扩展（Neo4j 集群）
  • 向量索引支持分片（LanceDB 支持 S3 存储）
  • 无状态 API 服务，支持水平扩容

8.3 可观测性

  • 日志：结构化日志，包含 request_id
  • 指标：Prometheus 格式，包含 QPS、延迟、错误率
  • 追踪：支持 OpenTelemetry 分布式追踪
  • 告警：错误率 > 1% 告警，延迟 > 1s 告警
